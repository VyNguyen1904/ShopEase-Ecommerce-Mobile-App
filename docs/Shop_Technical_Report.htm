2. Case Study

2.1 Business Scenario Overview

ShopEase is a consumer-to-consumer (C2C) and business-to-consumer (B2C) mobile e-commerce platform modeled after Shopee. The application enables sellers to list products and buyers to discover, purchase, and track orders — all within a unified mobile experience on Android.

 

2.2 Problem Statement

With the rapid growth of mobile commerce in Vietnam and Southeast Asia, small business owners and individual sellers need an accessible digital storefront. Traditional marketplaces require complex setup. ShopEase aims to provide:

•        A simple, intuitive interface for browsing and purchasing products

•        Real-time product search and category filtering

•        Secure cart and checkout with order tracking

•        Push notifications for order updates and promotions

•        In-app messaging between buyers and sellers

•        Store location discovery via integrated maps

3.4.2 Firestore Security Rules Overview

read: authenticated users can read products, categories. write: only the document owner (auth.uid == userId) can write their orders, cart, profile. Admin role (role == 'admin') can write products and categories.

4. Development Requirements

4.1 UI Implementation

All screens follow Material Design 3 with Shopee's orange color scheme (#EE4D2D). Key UI components include:

•        ProductCard widget: image, title, price, discount badge, rating stars

•        CategoryChip row: horizontal scroll of category icons

•        BannerCarousel: PageView with auto-scroll for promotional banners

•        CartItemTile: dismissible swipe-to-delete, quantity stepper

•        OrderStatusStepper: visual timeline (Placed → Processing → Shipped → Delivered)

•        ChatBubble: aligned left/right by sender, timestamp, read receipt

4.3 Firebase Integration

4.3.1 Firebase Auth

•        Email + Password authentication

•        Google Sign-In via google_sign_in package

•        Auth state stream listened in AuthProvider — redirects to Login or Home accordingly

 

4.3.2 Firestore Data Operations

•        Stream<QuerySnapshot> for real-time product list and chat messages

•        Future<DocumentSnapshot> for single product detail fetches

•        Batch writes for order creation (write order + decrement stock atomically)

 

4.3.3 Firebase Cloud Messaging (FCM)

•        FCM token saved to Firestore on login

•        Cloud Functions trigger notifications on order status change

•        flutter_local_notifications used for foreground message display

 

4.4 Deployment Requirements

4.4.1 Build Release APK

Steps to generate a signed release APK:

1.     Generate keystore: keytool -genkey -v -keystore shopease.jks -keyAlias shopease -keyalg RSA -keysize 2048 -validity 10000

2.     Configure android/key.properties with storeFile, storePassword, keyAlias, keyPassword

3.     Update android/app/build.gradle with signingConfigs block referencing key.properties

4.     Run: flutter build apk --release

5.     Output: build/app/outputs/flutter-apk/app-release.apk

 

4.4.2 Release Mode Proof

•        Screenshot of flutter run --release showing 'Running in release mode'

•        APK file size comparison: debug (~80MB) vs release (~25MB after tree-shaking)

•        Performance overlay screenshot showing consistent 60fps

6. Conclusion & Discussion

6.1 Summary

ShopEase successfully delivers a feature-rich Flutter e-commerce application covering all 10 required functions outlined in the PRM393 assignment specification. The app demonstrates proficiency in Flutter UI development, Firebase integration, Provider state management, and test-driven quality assurance.

 

6.2 Strengths (Pros)

•        Real-time data synchronization via Firestore streams — no manual refresh needed

•        MVVM + Provider architecture provides clear code separation and easy testability

•        Offline-capable cart (SharedPreferences) for a smooth user experience without network

•        Firebase Authentication handles security, token management, and session persistence

•        Google Maps integration offers genuine value to users finding nearby stores

•        Clean, consistent Shopee-inspired UI with orange brand identity

 

6.3 Weaknesses (Cons)

•        Firestore read costs can escalate at scale — no pagination was fully optimized

•        No seller dashboard: only buyer-side features are implemented in this version

•        Payment integration is simulated (COD only) — no real payment gateway (e.g., VNPay, MoMo)

•        Chat feature lacks image/file sharing capability

•        Map relies on always-on internet; no offline tile caching

 

6.4 Lessons Learned

•        Flutter's widget tree and reactive Provider pattern require careful state design upfront to avoid excessive rebuilds

•        Firestore security rules are critical — insecure rules were a common early mistake during development

•        Firebase Cloud Messaging setup on Android requires careful google-services.json placement and AndroidManifest configuration

•        Writing tests first (TDD) for CartProvider made later refactoring significantly safer

•        Using cached_network_image dramatically improved scroll performance in the product list

 

6.5 Future Improvements

•        Seller Portal: add a seller-side screen for listing management and order fulfillment

•        Real Payment Gateway: integrate VNPay or Stripe for actual transaction processing

•        Recommendation Engine: Firebase ML or a custom backend to suggest products based on browsing history

•        Lazy Loading & Infinite Scroll: cursor-based Firestore pagination for large catalogs

•        Dark Mode: full Material 3 dark theme support

•        Localization: Vietnamese and English language switching with flutter_localizations

•        CI/CD Pipeline: GitHub Actions to run flutter test and deploy to Firebase App Distribution
